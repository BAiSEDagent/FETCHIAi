CP2.7G — Today’s Run front-card polish

The current Today’s Run direction is correct. Do not roll back. Keep the no-flip, card-first swipe model. This is now a visual/product polish pass.

Fix the following only:

1. Progress bug
- The progress bar currently appears partially filled even when the text says 0/2 and 0 reviewed.
- At 0 reviewed, the progress fill should be 0%.
- Progress fill should equal reviewed / total.
- Keep the compact MORNING REVIEW module.
- No time-pressure copy.

2. Make the card feel more valuable
The front card needs to feel like a lead dossier, not a summary card.
Keep the card frame stable, but make the internal content area scrollable if needed.

Add a compact “Evidence stack” section on the front card with 3–5 rows when data exists:
- Storm report / weather event
- Property record / address
- Permit / roof age / construction signal
- Ownership / business filing
- Contact route / best contact
- Market confirmation if available

Each evidence row should be compact:
- small icon or signal marker
- uppercase category label
- bold evidence title
- muted source/date line
- confidence dots or “verified” cue if available

Do not create a back side. Do not reintroduce flip.

3. De-emphasize buttons
The card should dominate the screen.
The action row should feel secondary, not like three giant CTA tiles.

Mobile action row:
- Keep only two compact pill actions as fallback:
  - Pass
  - Add
- Add should remain primary green.
- Pass should be neutral/ghost.
- Reduce height and visual weight.
- Make the row read as optional controls beneath the card.
- The primary interaction remains swipe:
  - swipe left = pass
  - swipe right = add

Add a small subtle hint near the bottom of the card or above actions:
“Swipe left to pass · right to add”

Do not make “Open lead” compete visually.
Keep Open lead as a small text link inside the card footer.

4. Card sizing / scrolling
- The outer card frame should stay the same height between leads.
- Static elements stay static:
  - mobile header
  - progress module
  - card frame
  - bottom nav
- If evidence exceeds available space, only the card’s internal dossier area scrolls.
- Do not allow the entire page to awkwardly scroll during normal review state.

5. Copy
Use:
- “Draft prepared, not sent” only if a draft exists.
- Add confirmation toast: “Added to My Leads. Draft prepared, not sent.”
- Pass copy remains honest: “Tagged. Fetchi will use this feedback to improve future stacks.”

Remove / avoid:
- “ready to queue”
- “time to clear”
- “quick”
- “faster”
- any speed/rush framing

Architecture guardrails:
- No schema changes.
- No new statuses.
- Today’s Run remains a session view over opportunities.
- Add = status saved.
- Pass = status skipped + structured outcome_notes.
- No changes to My Leads, Lead Detail, Chat, Map, Settings, Admin, Billing, Agents, Providers, Stripe, schema, seed, drizzle, db/index, package.json, or design files.
