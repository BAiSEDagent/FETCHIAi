CP2.7F — Today’s Run Card-First Swipe Review

The current Today’s Run card is closer visually, but the flip/evidence-back interaction is adding unnecessary complexity. Remove the radical flip model. Today’s Run should be a premium swipe deck where the lead card itself contains the valuable evidence and data on the front.

Core direction:
The card is the product moment. Make one large, data-rich lead card dominate the screen. The user reviews the lead, then swipes left to pass or swipes right to add to My Leads.

Do not make this feel like a timed task. Remove all time-to-clear copy. No “~1 min”, “~30s”, “quick clear”, or speed-based language.

Layout:
- Keep Fetchi mobile header unchanged.
- Keep MobileBottomNav unchanged with Today active.
- Keep the page mostly static on mobile.
- Progress module should be compact:
  - Eyebrow: MORNING REVIEW
  - Main: 2 high-fit leads ready
  - Progress pill: 0/2
  - Footer: 0 reviewed · 2 left
- Remove redundant large “Today’s Run” title if it causes crowding on mobile.
- The lead card/deck should visually dominate the remaining viewport.

Remove:
- Remove the card flip interaction.
- Remove “Evidence / Back” flip button.
- Remove giant CTA tiles/buttons.
- Remove oversized bottom action row.
- Remove card-back layout.
- Remove any duplicated ghost card layers that make the layout look broken.

Card front:
Make the front card feel like a valuable lead dossier. It should include all important information directly on the card:
- Signal token chip, e.g. HAIL · 1.8" · 5D
- Optional No claim filed chip
- Business name
- Location + humanized business type + size if available
- Circular FIT score badge
- Reason ribbon, e.g. “88 — Same storm + commercial roof”
- Why Now summary
- Evidence section with compact evidence rows/chips:
  - Storm report/date/source
  - Property record/address
  - Permit or roof age if available
  - Ownership / SOS if available
  - Market confirmation if available
- Best contact row with role and confidence dots
- Draft status if available: Draft prepared, not sent

Scrolling:
- The page itself should not awkwardly scroll during the review state.
- The card should have a fixed visual frame.
- If the card has more evidence/data than fits, make the card’s internal content area vertically scrollable.
- The outer card size must stay stable.
- Static elements stay static:
  - header
  - progress module
  - card frame
  - bottom nav

Swipe behavior:
- Swipe left on the card = Pass.
- Swipe right on the card = Add to My Leads.
- Use pointer events / touch events only. Do not add a new npm dependency.
- Show a tasteful overlay during drag:
  - Left drag: PASS
  - Right drag: ADD
- After successful action, animate the card offscreen and advance to the next lead.
- Keep prefers-reduced-motion support.

Pass behavior:
- Swipe left should open the existing PassReasonPanel before finalizing, unless the current implementation already requires a reason.
- Pass writes status="skipped" and outcome_notes with the existing structured payload.
- Copy must stay honest: “Tagged. Fetchi will use this feedback to improve future stacks.”
- Do not claim exclusions, suppressions, or re-weighting logic.

Add behavior:
- Swipe right sets status="saved".
- Show a small confirmation toast/inline message: “Added to My Leads. Draft prepared, not sent.”
- Then advance to next lead.

Tap behavior:
- Tapping the card or a subtle “Open lead” text link can navigate to /app/leads/[id].
- Do not make Open Lead visually compete with swipe actions.

Desktop:
- Desktop can keep a centered card deck with subtle keyboard hints:
  - ← Pass
  - → Add
  - Enter Open lead
- Do not make desktop a CRM table.

Completion:
- When the queue is complete, show:
  - Stack cleared
  - You reviewed N opportunities
  - Added count
  - Passed count
  - Drafts prepared count
  - CTA: Back to My Leads

Architecture guardrails:
- Today’s Run remains a session view over opportunities.
- No new status.
- No new schema.
- Add -> status="saved"
- Pass -> status="skipped"
- Preserve outcome_notes behavior.
- No edits to schema, seed, drizzle, db/index, package.json, design files, billing, admin, agents, providers, Stripe, Chat, Map, Settings, My Leads, or Lead Detail unless absolutely required for imports/types.

Relevant files likely:
- app/app/today/page.tsx
- components/app/TodaysRunView.tsx
- components/app/LeadCard.tsx if run variant is still used
- existing pass reason components/actions

Run:
- npm run type-check
- npm run build

Report and stop.
